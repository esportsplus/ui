Native scrollbar-width / scrollbar-color — scroll each panel

thin + custom color (the replacement)

This panel uses only two CSS properties: scrollbar-width: thin and scrollbar-color: #e0245e #3a1a24. No JavaScript, no negative-margin tricks, no ::-webkit-scrollbar reset.

scrollbar-color takes two values: the first is the thumb (red here), the second is the track / rail (dark red). Both are fully controllable cross-browser.

The width keyword is thin — the browser and OS pick the exact pixel size. You cannot force 4px here, and the thumb has no border-radius (square ends).

Scroll up and down to see the native thumb move. On macOS it will overlay and auto-fade; on Windows it reserves a gutter (that is what scrollbar-gutter: stable guarantees, so content does not shift when the bar appears).

hidden (scrollbar-width: none)

Fully hidden scrollbar — still scrollable by wheel/touch. This is the modern one-line replacement for the transparent ::-webkit-scrollbar reset.

If you wanted a purely synthetic overlay bar (like your current component) you would hide the native one this way, then draw your own div on top.

no arrows + square (::-webkit-scrollbar)

This panel uses ::-webkit-scrollbar for full control: ::-webkit-scrollbar-button { display: none } removes the arrows, and ::-webkit-scrollbar-thumb { border-radius: 0 } gives square corners. Width is 5px, with a small border-radius: 2px. Hover the thumb (brightens to a lighter red) and the rail (darkens) — both use :hover on the pseudo-elements. WebKit/Blink only.

Works in Chrome / Edge / Safari. Firefox ignores all of this and falls back to scrollbar-width: thin + scrollbar-color declared in the same rule — which also has no arrows, so both engines end up arrow-free.

The trade-off: two code paths, and only WebKit/Blink honors the square corners and exact width. Firefox stays at its own thin rendering.
